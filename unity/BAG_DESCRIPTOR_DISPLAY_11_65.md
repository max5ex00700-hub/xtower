# 11.65 가방 상단 수식어 배수 표시

기준 HEAD: `2f3090c18c2ce5193fbb8503341d04ae93435161`.
수정 전 원격 unity-prototype이 같은 HEAD임을 확인했다.
사용자 첨부 `32332.jpg`와 실제 소스를 확인했다.

## 원인

XTapInventory.Render는 현재 가방에 착용한 item.attack / defense / hp를
그대로 더해서 상단에 출력했다. DescriptorSetMultiplier를 적용하지 않았다.
반면 XTapBattleController의 CurrentPlayerAttack/Defense/MaxHp는 이미
`(기본 플레이어 능력 + 모든 유효한 착용 블럭 능력) × DescriptorSetMultiplier`
로 계산하고 있었다. 가방 표시 경로에서 배수가 누락된 문제다.

## 수정

범위: 플레이어 가방, 각 캐릭터 가방, 감옥 목록·상세, 메인 정보창.

- 가방 상단 합계에 전투와 동일한 DescriptorSetMultiplier를 적용한다.
  현재 열린 가방의 장비 기여분만 표시하며 기본 플레이어 능력은 포함하지 않는다.
- 별도 행에 `이 가방 장비 합계 · 전체 수식어 ×2 적용`처럼 적용 배수를 표시한다.
  수식어 장비가 없으면 ×1이다. 두 행이 잘리거나 그리드에 가려지지 않게
  상단 정보 영역을 늘리고 그리드 시작 위치를 조정했다.
- 배수는 기존 규칙대로 플레이어 가방과 포획된 캐릭터 가방의 착용 장비에서
  합산한다. 소지품·바닥·미포획 캐릭터 가방은 배수에 포함하지 않는다.
- 합계의 음수 제외와 넘침 상한을 전투의 장비 계산에 맞췄다.
- 가방·감옥 목록·상세는 GetBagDisplayStats를 공통으로 사용한다.
  감옥 목록 행과 상세 영역도 배수 행을 넣을 수 있도록 높이를 확보했다.
- 메인 정보창에는 `수식어 ×2` 표시를 추가했다. 메인 공·방·체는 원래부터
  CurrentPlayer*의 배수 적용 결과를 사용하므로 또 곱하지 않는다.
- 블럭 자체 수치, 저장 데이터, EquippedAttack/Defense/Hp, 전투 계산은
  변경하지 않았다. 전투에 배수가 두 번 적용되지 않는다.
- EndDrag가 착용/해제 후 Save→Render를 호출하고, TidyBag 및 대장간 변경도
  Render를 호출하는 경로를 읽어 배수와 합계의 갱신을 확인했다.

예를 들어 이 가방의 배수 전 합계가 공 100 / 방 50 / 체 200일 때의 수식:

| 유효한 착용 수식어 블럭 | 전체 배수 | 가방 상단 장비 합계 |
| --- | --- | --- |
| 없음 | ×1 | 100 / 50 / 200 |
| 수식어 1개 블럭 하나 | ×2 | 200 / 100 / 400 |
| 수식어 1개 블럭 둘 | ×4 | 400 / 200 / 800 |
| 수식어 1개·2개·3개 블럭 각 하나 | ×10 | 1000 / 500 / 2000 |

위 표는 수식 설명용 예시이며 사용자 저장 데이터나 Unity 실행 결과가 아니다.
첨부 사진의 축약된 합계만으로 정확한 원래 수치와 저장 상태를 알 수는 없다.

## 검증 범위

- 이전 HEAD와 비교: 착용 판정, 수식어 점수·배수, 원시 능력치 접근자 영역과
  CurrentPlayerAttack/Defense/MaxHp 계산이 변경되지 않았음을 실제 비교했다.
- 1080×1920/2340/2400/2520 배치 계산에서 배수 행, 합계 행, 그리드 경계 분리
  및 텍스트 영역 높이를 검사했다. Unity 글꼴 렌더링 검사는 아니다.
- `git diff --check` 통과. 바이너리 에셋은 변경하지 않았다.
- 이 환경에 Unity/C# 컴파일러가 없어 Unity 컴파일·Cloud Build·APK 실행은
  미실행이다. 다음 실기기 확인은 수식어 장비 하나를 착용/해제하면서
  ×2↔×1 및 상단 세 수치가 함께 바뀌는지 확인하는 것이다.
