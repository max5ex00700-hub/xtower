# 블럭 머신 0 선택 확률 수정 11.76

기준 커밋: `5e4d8787f7a402f24014189e858d85320beb2f0a`.
사용자 지시: 0 선택 시 포획 확률은 1%, 캐릭터 블럭도 1%.

## 실제 확인한 이전 동작

`XTapGachaMachine.RollOutcome`의 미포획 분기는 이미
`Random.Range(0, 100) == 0`으로 포획 확률 1%를 적용했다.
포획한 캐릭터의 0 분기에는 확률 검사가 없어 전용 블럭을 항상 생성했다.
사용자 기기에 설치된 APK의 버전/동작을 직접 확인한 것은 아니다.

## 적용 규칙

전투 보상 룰렛에서 0이 선택된 뒤 아래 확률을 적용한다.

| 캐릭터 상태 | 성공 1% | 실패 99% |
| --- | --- | --- |
| 미포획 | 해당 캐릭터 포획 저장 | 포획 실패, 보상 없음 |
| 이미 포획 | 해당 캐릭터 전용 블럭 생성 | 획득 실패, 보상 없음 |

- 두 분기가 `Random.Range(0, 100) == 0`이라는 한 번의 동일한 판정을 공유한다.
  0~99의 정수 중 0 한 가지가 성공이며 포획과 블럭을 연속 두 번 추첨하지 않는다.
- 결과 화면에 `0 선택 · 포획 1%` 또는 `0 선택 · 전용 블럭 1%`를 표시한다.
- 전용 블럭 실패 결과를 별도로 표시하며 빈 보상을 일반 블럭으로 대체하지 않는다.
- 성공한 블럭만 기존 수령 처리로 바닥에 저장한다.
- 0 이외의 보정값, 일반 블럭 능력치/수식어, 룰렛 칸 선택 확률을 유지한다.
- 무료 시간 티켓은 기존처럼 일반 블럭을 지급하며 포획/전용 블럭 추첨 경로를 사용하지 않는다.
- 11.75 오디오 출력 수정도 포함한다.

버전: `11.76-unity6-<commit>` / Android versionCode `1176`.
Unity: `6000.3.24f1` 유지.

변경 함수의 확률 조건, 저장/수령 분기, 실패 표시와 기존 무료 티켓 경로를 정적으로 확인했다.
프로젝트 C# 25개의 문법 파싱, 11.76/1176 일치, `git diff --check`를 통과했다.
기존 티켓 처리·일반 블럭 생성·수식어·수령·룰렛 회전 함수가 변경되지 않았음을 대조했다.
실제 Unity 컴파일, Cloud Build, APK 설치 및 기기 추첨 테스트는 별도 확인이 필요하다.
