# 11.65 미접속 시간당 티켓 초기화 순서 수정

기준 HEAD: `2f3090c18c2ce5193fbb8503341d04ae93435161`.
사용자는 미접속 시간 보상이 생기지 않는다고 보고했다.
APK 실행 로그와 PlayerPrefs 저장본은 전달받지 못했다.

## 소스에서 확인한 손실 경로

11.64는 티켓 저장값을 Start에서 읽었다. 반면 OnApplicationPause는
초기화 여부를 확인하지 않고 AccrueHourlyTickets를 호출했다.
아직 읽지 않은 필드는 count=0, anchor=0이므로 AccrueHourlyTickets가
현재 시각을 새 기준으로 잡고 0장과 함께 PlayerPrefs에 저장한다.
그 다음 Start가 이 덮어쓴 값을 읽으면 미접속 시간이 사라진다.

Unity 2022.3 공식 OnApplicationPause 문서에는 Awake 직후 초기화 중에도
false 이벤트가 발생한다고 명시되어 있다. 이 순서와 기존 코드를 대조해
실제 저장값을 잃을 수 있는 경로를 확인했다. 사용자 기기에서 어느 콜백이
실행됐는지 직접 추적한 것은 아니다.

https://docs.unity3d.com/2022.3/Documentation/ScriptReference/MonoBehaviour.OnApplicationPause.html

## 수정

- Awake에서 저장된 티켓 수와 기준 시각을 먼저 읽는다.
- loaded 플래그로 Load를 한 번만 수행한다. Start의 기존 호출은 재로딩하지 않는다.
- 로딩 전 Accrue/Save/Consume/UI 갱신은 즉시 반환한다. 초기 콜백이
  먼저 와도 기본값으로 저장 데이터를 덮어쓰지 않는다.
- 앱 포커스를 되찾을 때도 정산한다. Pause/Focus/Update가 연이어 와도
  이미 지급한 정수 시간만 기준 시각에 더하므로 중복 지급하지 않는다.
- UTC 3600초당 1장, 기존 티켓 보존, 남은 분·초 이월, 시계 역행 처리,
  보상을 바닥에 저장한 뒤 차감하는 기존 순서를 유지한다.
- HOURLY_TICKET_LOAD, HOURLY_TICKET_ACCRUE 로그에 저장값·경과 시간·
  지급 수·잔여 시간을 남겨 후속 Android 로그로 판단할 수 있게 했다.

확인할 회귀 시나리오:

| 저장 상태/동작 | 기대 결과 |
| --- | --- |
| 저장 2장, 기준에서 3시간 30분 후 재실행 | 5장, 다음 지급까지 30분 |
| 저장 0장, 59분 경과 | 0장, 남은 1분 이월 |
| 위 상태에서 1분 후 복귀 | 1장 |
| 지급 직후 Pause/Focus 반복 | 중복 지급 없음 |
| 저장값을 읽기 전 초기 콜백 | 기존 PlayerPrefs 변경 없음 |
| 새 설치, 기준 시각 없음 | 현재 시각을 저장하고 1시간부터 적립 |
| 저장 2장, 시계가 기준보다 과거로 변경 | 2장 유지, 시간 기준만 재설정 |

위 표는 기대 동작이며 Unity 실행 테스트 통과 기록이 아니다.
이 환경에는 Unity와 C# 컴파일러가 없다. 코드 순서·보호 조건·호출 경로와
diff를 검토했으나 Unity 컴파일, Cloud Build, Android 재시작/복귀 테스트는
미실행이다. 이미 덮어쓴 과거 시간/티켓은 별도 기록 없이는 복원할 수 없다.

이번 11.65에는 가방·감옥·메인 정보창의 수식어 배수 표시 수정도 함께 포함한다.
